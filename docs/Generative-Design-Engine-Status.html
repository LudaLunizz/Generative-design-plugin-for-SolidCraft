Generative Design Engine - Status

SolidCraft plugin · version 0.2.0 · 17 Nov 2026 · ~/project SolidCraft/generative-design-engine (local git)
In short: the 0.1 plugin did not work and its results were made up. It is rebuilt as a real SolidCraft component with an 11-material engineering library (SolidCraft's own material cards) and a per-body material report. It is installed in SolidCraft 0.42 and passes an end-to-end test there. Generative design and stress analysis are withdrawn until a real solver backs them.

What was wrong in 0.1

  • plugin.wasm was SolidCraft's sample test component (it makes two boxes), not this plugin's code. The Rust code was never built to WebAssembly.
  • optimize and analyze returned invented numbers: a fixed "original volume", stress = max_stress x 0.7, and the same critical point (25, 0, 0) for every part.
  • The manifest would be refused: it granted the non-existent command commands.run, asked for a 300 s deadline (max 30 s) and 512 MiB (default ceiling 128 MiB).
  • The material "library" was one default, with density in the wrong unit (2.7e-6).

What 0.2 does

EntryEffectWhat it does
apply-materialeditCreates the library material once (density, look, full engineering card) and assigns it; empty body list = all bodies. One undo step.
material-reportreadPer body: material, volume, mass, E, yield/tensile and allowable stress = strength / safety factor.
materialsreadLists the library.

In SolidCraft: Model tab, Plugins group/menu. The report gives the allowable stress, not the stress in the part: no solver runs.

Hardening

  • Hostile input refused before any edit (unknown fields, non-objects, bad numbers, empty, duplicate or oversized body names). No unwrap/expect/panic/indexing outside tests (clippy-denied).
  • Host errors pass through, so SolidCraft rolls back; cancel is checked before each edit; a same-named design material with other values is never overwritten.
  • Limits 2e9 fuel / 64 MiB / 15 s, inside the default ceilings. The component imports only craft:plugin (no WASI); build.sh refuses anything else.
  • plugin.json is generated from the library; a test fails if they drift.

Tests

  • 24 Rust tests (library validation, fake-host tests of every entry, hostile params, manifest rules).
  • tests/cli-test.sh in the installed SolidCraft 0.42: all 11 materials pass SolidCraft's card check, masses correct, reapply reuses, undo, bad input refused, the saved design reopens with its materials without the plugin. Result: PASS.

SolidCraft 0.42 findings

  • material.list and material.inspect only read but are not marked read-only, so a read entry may not call them. The report takes strengths from the library and checks the measured density.
  • 0.42's plugin.install takes only path, replace and dry_run (the docs describe a newer one with approvals).

Next

  • Generative design: needs a real solver. Options from the 28 Oct research: a voxel SIMP/FEA solver inside the plugin (wasm, deadline 30 s, mesh up to 8192 vertices), or NITO/TopoDiff models outside it.
